# IDS Dataset and Evaluation Audit

## Dataset

The recorded IDS experiment contains 56,694 window samples from 124 simulation runs.
The manifest is `results/raw/ids/manifest.json`; dataset metadata is
`results/raw/ids/dataset_info.json`.

| Item | Recorded value |
|---|---|
| Dataset | D2D-SIM, generated by `backend/app/ids/dataset.py` |
| Runs | 124 |
| Rows/windows | 56,694 |
| Attack kinds | 9 traffic attack kinds plus benign |
| Attack rates | 3, 10, 30 packets/s |
| Seeds | 101, 102, 103, 104 |
| Swarm sizes | 8, 10, 12 |
| Duration | 45,000 ms per run |
| Test fraction | 0.30 by run |
| Classes | 10 |
| Operational model | XGBoost selected by training-split grouped CV macro-F1 |
| Public NSL-KDD | Not run; files were unavailable |

Class distribution:

| Class | Windows |
|---|---:|
| benign | 52,744 |
| dos | 1,741 |
| impersonation | 320 |
| unauthorized_access | 304 |
| abnormal | 293 |

The largest/minority ratio is 248.79:1. Accuracy alone is therefore misleading;
macro-F1, per-class recall, binary FPR/FNR, and confusion matrices are required.

## Features and target

The live feature list is `app/ids/features.py:FEATURES`. It contains counts, sizes,
inter-arrival statistics, protocol fractions, authentication outcomes, integrity/replay
verdicts, sequence anomalies, command counts, source role, and verified counts.

The multiclass target is `label` for training/evaluation. Live extraction calls
`extract_windows(..., with_labels=False)`, so live features do not include the target.
The binary display metric is `1 - P(benign)` in `SecurityMonitor._ids()`.

## Leakage audit

The implementation explicitly forbids `true_src`, `label`, `attack_id`, and simulator
drop-ground-truth fields from features. `TrafficLog.observable()` and
`extract_windows()` use receiver-observable fields and receiver-side verdicts. The
feature extractor also removes unobservable channel losses and policy drops.

The recorded validation report shows:

- NaN cells: 0
- infinity cells: 0
- negative count values: 0
- group overlap: 0 runs
- cross-split exact duplicates: 98 test rows (0.5223%)
- duplicate label conflicts: 1
- near-perfect single features: none

This supports “no hard ground-truth leakage was detected, and train/test groups were
disjoint.” It does not support “there are no correlated windows,” because 98 exact
feature duplicates cross the split. The project reports a deduplicated robustness
evaluation; this is the correct qualification.

## Split and validation

`ids/validation.py:group_split()` splits by `run_id`, stratified by `scenario_kind`.
This avoids placing adjacent windows from one simulated run in both train and test.
`ids/models.py:train_model()` uses `GroupKFold` inside the training set for model/grid
selection. Preprocessing is fitted inside the sklearn pipeline on training folds.

Random row splitting would be optimistic because adjacent windows from one run share
traffic configuration, topology, target, seed, and attack timing.

## Preprocessing and models

Every candidate uses the same pipeline: clip nonnegative values, `log1p`, standardise
numeric fields, then classify. Class imbalance is handled through balanced class/sample
weights. Candidates are Logistic Regression, Decision Tree, Random Forest, and XGBoost.
The operational model is selected by maximum grouped-CV macro-F1, not test accuracy.

## Results interpretation

Recorded held-out test results are in `results/processed/ids/metrics_all.csv` and
per-class results in `per_class.csv`. XGBoost has test macro-F1 0.9439, weighted-F1
0.9959, binary F1 0.9856, FPR 0.000803, and FNR 0.01813. The XGBoost per-class F1 is
weakest for `abnormal` (0.7952) and `replay` (0.8961), despite high overall accuracy.

The unseen-low-rate robustness split is materially weaker: macro-F1 is approximately
0.77 for Logistic Regression, 0.83 for Decision Tree, 0.77 for Random Forest, and
the corresponding XGBoost row must be read from the recorded metrics file. This is an
important generalisation warning.

## Audit conclusion

The IDS methodology is defensible for a simulator study: run-level split, grouped CV,
pipeline-fitted preprocessing, leakage checks, per-class metrics, duplicate robustness,
and unseen-rate evaluation are present. The boundary is that D2D-SIM is synthetic and
NSL-KDD/external IoD validation was not run.
