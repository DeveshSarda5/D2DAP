# Results and Evaluation

## 1. Experimental setup

The project evaluates a deterministic software simulation of D2DAP-secured drone
traffic. Existing reports are generated by `scripts/run_experiments.py` and include
manifests, raw data, processed metrics, table/figure provenance, seeds, package
versions, and Git commits.

The results below are recorded results, not fresh reruns on the current laptop. The
current HEAD is `64b9b7f`; result manifests identify earlier commits. This distinction
is part of the result, not hidden.

## 2. ML results

The D2D-SIM dataset has 56,694 rows, 124 runs, 10 classes, and a 248.79:1 largest to
smallest class imbalance. Run-level grouped splitting yielded zero train/test run
overlap. Existing model comparison is in `results/processed/ids/metrics_all.csv`.

| Model | Accuracy | Macro precision | Macro recall | Macro F1 | Weighted F1 | Binary F1 | FPR | FNR |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Logistic Regression | 0.9679 | 0.8068 | 0.9437 | 0.8388 | 0.9766 | 0.8193 | 0.0329 | 0.0053 |
| Decision Tree | 0.9923 | 0.9201 | 0.8797 | 0.8959 | 0.9920 | 0.9593 | 0.0018 | 0.0566 |
| Random Forest | 0.9956 | 0.9734 | 0.9103 | 0.9355 | 0.9953 | 0.9832 | 0.0003 | 0.0295 |
| XGBoost | 0.9960 | 0.9537 | 0.9405 | 0.9439 | 0.9959 | 0.9856 | 0.0008 | 0.0181 |

XGBoost is selected because it has the highest training-split grouped CV macro-F1
(0.9535), not because the test set was used for selection. Its per-class F1 is in
`results/processed/ids/per_class.csv`; the weakest recorded classes include `abnormal`
(0.7952) and `replay` (0.8961).

## 3. Authentication

Recorded P-256 hint MAKA mean latency is 32.099 ms, median 31.480 ms, P95 37.826 ms,
two messages, 304 bytes, and 44 counted operations/authentication. P-256 trial peer
resolution increases mean latency to 49.556 ms and operations to 56.33. These are
software measurements on the recorded host and compute-only unless a scenario says
otherwise. They are not Raspberry Pi or energy measurements.

## 4. Baseline comparison

Existing A-D summary (`results/processed/baseline_comparison/summary.csv`):

| System | Detection | Mitigation | Median response ms | Disruption | Framed |
|---|---:|---:|---:|---:|---:|
| A D2DAP only | 0.6667 | 0.6818 | n/a | 0 | 0 |
| B D2DAP+IDS block | 1.0000 | 0.9560 | 1100 | 0.0007 | 1 |
| C IDS+trust binary | 1.0000 | 0.7778 | 2600 | 0 | 0 |
| D full adaptive | 1.0000 | 0.9549 | 2200 | 0 | 0 |

Interpretation: authentication alone misses insider behaviour; naive IDS blocking is
fast but frames identities in these scenarios; the full adaptive layer retains high
mitigation with no recorded disruption/framing in this experiment, at higher response
latency than the naive blocker.

## 5. Ablation

Existing ablation data shows the roles of components:

- removing trust increases mitigation but gives `framed_rate=1` in the recorded setup;
- removing ML increases disruption and lowers mitigation;
- removing policy leaves detection but loses response/mitigation;
- removing attribution preserves response but increases framing;
- removing ML is a heuristic ablation, not a second trained detector.

These are controlled simulation results, not universal guarantees.

## 6. STRIDE coverage

The implementation covers spoofing, tampering, repudiation analysis, information
disclosure, denial of service, and elevation of privilege through concrete attack
classes and/or protocol analysis. Repudiation is partial: signed M1/M2 are
judge-verifiable, while symmetric data-plane messages remain forgeable by either session
peer. Passive eavesdropping is not detectable by the IDS in the current model.

The detailed recorded table is `results/tables/stride_table.csv` and the raw run data
is `results/raw/stride/stride_runs.csv`.

## 7. Scalability and limitations

Recorded sequential scalability reaches 100 drones. Trial-decryption authentication
latency grows from roughly 37.5 ms at 5 drones to 293.5 ms at 100 drones; monitor
processing grows from roughly 76.5 ms to 133.6 ms per window. This supports a simulator
scaling observation, not a real embedded deployment capacity claim.

The project cannot establish physical PUF security, real RF behaviour, energy
efficiency, formal proof reproduction, or real-world ML generalization. The IDS result
also has a low-rate generalization gap and class imbalance.

## 9. Interpretation rule

Every number in a thesis table should identify: experiment name, seed/configuration,
metric definition, source CSV, and manifest Git commit. Do not present an existing
result as a current-HEAD rerun until it has been regenerated at current HEAD.
